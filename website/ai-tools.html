What is actually happening

No black box — here is the whole pipeline, in order.

1
The model loads into this tab

A 64 MB Real-ESRGAN export is fetched once and handed to ONNX Runtime compiled to WebAssembly. It is then cached, so a second visit does not download it again.

2
Your image is decoded and cut into tiles

The file is drawn to a canvas, sliced into overlapping tiles and normalised to the float range the network expects. This all happens in memory inside the page.

3
Tiles are blended back into one picture

Each tile is upscaled 4×, the overlap is cropped off, and neighbouring tiles are averaged so the seams do not show. Then you get a download button.

Why speed depends on your device

The same model runs on a phone and on a desktop GPU, and the difference is large. These are measured reference points, not promises about your machine.

What is on chain, and what is not

On chain: the escrow, which provider was assigned, the keccak256 of the result, the settlement and any slashing — all readable with one getJob(jobId) call. Not on chain: the image itself. No EVM can hold a megabyte of pixels, so the bytes travel out of band and the chain carries only their hash. Right now no provider process is serving testnet jobs, so a job you create will be escrowed and stay in ESCROWED until one is. The escrow is real and refundable through cancelJob; the transport is the piece still being built.

Boundaries

What this tool will and will not do

🔒

It will not upload your image

There is no upload endpoint. The runtime and the model file are the only things fetched from the network, and both are static assets. You can watch the network tab and see for yourself.

🐢

It will not be fast on weak hardware

Speed is a property of your device, not of the page. If you are on integrated graphics, start with a small image and expect to wait. There is no server-side fallback here by design.

🧾

It will not pretend to be the network

No wallet, no token, no fake job counter. It is a tool, labelled as a tool. The chain-backed service is a separate page with its own escrow, verification and penalties.

Why build the free tool first. The network's honest weakness is that it has no jobs yet. A tool that is useful on its own — even with the chain switched off — earns attention before it asks anyone to trust a marketplace. This page is that first step; the paid side is built to be earned, not assumed.
