Agent economy

Compute for the Agent Economy

Always-on inference, machine-to-machine payment, and settlement per verified result.

Omniverse Compute (OMC) is building the settlement layer for the agent economy: autonomous software buys GPU time, pays for verified results, and settles machine-to-machine on BNB Chain. The unit of commerce moves from a reserved GPU hour to a completed, checkable inference — the only thing an agent actually consumes.

From GPU hours to verified outcomes

Cloud pricing starts with a reservation: rent a box for an hour, keep the queue short, pay whether the job succeeds or not. An always-on agent has the opposite shape. It emits thousands of small requests, each with a result that can be checked, and it needs a price attached to that result rather than to the idle hardware around it.

OMC prices compute at the outcome. A requester escrows the job, a node runs it, and the release condition is the verifiable completion of that job. Matching, staking and settlement sit behind that one sentence — the commercial interface stays deliberately small: one request, one result, one settlement.

Machine-to-machine payment is the default

Agents do not fill in billing forms. They need a credential, a meter and a way to top up without a human in the loop. OMC's tool endpoints use prepaid credits redeemed against an on-chain transfer: the service verifies the transaction on BNB Chain, debits one unit per completed job, and returns the unit when inference fails. The server holds no private key, and tool revenue is accounted for separately from every other flow in the project.

That pattern scales down to sub-cent requests and up to long-running agents that buy capacity continuously. It is also the shape on-chain settlement was built for: small, frequent, auditable transfers between two programs.

Why inference, and why now

Training is episodic; inference is continuous. As agents move from demos into production, the demand curve stops resembling a quarterly batch job and starts resembling a utility bill. The bottleneck shifts from raw FLOPS to availability, verification and settlement latency — the three things a decentralized grid competes on.

Routing therefore treats verification as a dial. Spot-check re-execution suits batch work; redundant execution across independent nodes suits high-stakes results; hardware TEEs suit confidential workloads. Requesters choose the policy and pay for the assurance their job needs. The verifiable compute page describes the ladder.

Questions

What does an agent actually pay for?

A completed result that passes the verification policy chosen for that job. Hardware time is an input to the node's own economics, not the line item on the requester's invoice.

Who holds the funds while a job runs?

The job fee sits in escrow and releases when the verifiable end state is reached. For metered tool traffic, prepaid credits are debited per completed call and returned when a call fails.

Where does this go next?

Agent-facing APIs, continuous metering, and a verification ladder priced by risk. Each stage is published on the news page and in the whitepaper.
