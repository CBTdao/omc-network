# OMC AI Tools · 收费工具选型（收入线 1）

> 目标：把已有算力包装成「按次付费的成品服务」，产生第一笔外部资金流入（真造血）。
> 选型日期：2026-11-03。定稿后按「落地顺序」执行，不追加大件。

## 选型标准（三条全满足才入选）

1. **跑得动**：GTX 1050 / 4GB / Pascal（无 FP16）。单张推理 ≤10 秒，模型 ≤500MB，ONNX 生态。
2. **边际成本低**：复用 `p0-worker/server.py` + `p0-web/index.html` 的上传→处理→下载骨架，
   最多加一个模型文件 + 一条路由。
3. **外部付费市场已验证**：有人正在为同类结果付钱（remove.bg、淘宝照片修复等），我们不发明需求。

## 不做清单（明确排除，防止跑偏）

- **SD 生图**：4GB Pascal 一张 20–30s 体验差，且全网免费得多——红海必死
- **视频超分/转码**：1050 算力不够，排队体验不可接受
- **LLM 推理**：4GB 显存跑不动有竞争力的模型
- **企业 SLA / B2B 定制**：个人主体不接

## 支付路径（两阶段）

1. **阶段 1（现在→主网）**：BNB 直付到 **AI 工具专用收款账户**，server 读链验证交易哈希后发放额度。
   - 配置在 `p0-worker/payments.json`（`scope: "ai-tools-only"`），当前地址 `0x838EDFBA…b0A`（EIP-55 校验通过）。
   - **账户隔离（硬约束）**：这个地址**只收工具的钱**。空投的 0.01 BNB/份是另一条资金管道——由未来的 `claim()` 合约在链上收取、按 60/40 两笔转账分账；`contracts/params.json` 里 `treasuryAddress` 仍为 `null`，真合约与多签 Safe 一起部署时才确定。两者不得填成同一个地址，`test_payments.py` 有护栏用例盯着。
   - **预付额度（credits），不是每单上链**：BSC 单笔转账 gas 比 $0.01 的定价贵 7–30 倍，所以一次充值换 N 次额度，链下按次扣减；推理失败自动退 1 次。
   - 工具账户流水单独记账、公开，不与空投手续费合并。
2. **阶段 2（主网后）**：OMC 支付享折扣（例：标价 10% off），走 `OMCComputeMarket` escrow，
   8% 协议费 → 4% 销毁——空投出去的 OMC 由此变成生态内消费力。
